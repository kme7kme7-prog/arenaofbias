# 后台用户管理页（app/admin/users.tsx + /api/admin/users 组）

## 服务端（server/index.js，沿用 requireAdmin + 同源 + JSON 校验模式）

1. **`GET /api/admin/users`**：分页（默认 50，钳 1–200）+ 关键字搜索（用户名/邮箱 LIKE）。每行：id、username、role、email（老账号可能为空显示 —）、emailVerified、createdAt、votes/comments 计数（子查询）。倒序。
2. **`PATCH /api/admin/users/:id`**：body `{role: 'admin'|null}` 授权/撤权。**防呆：不能操作自己的账号**（防自锁，服务端硬校验 400）。dev/ADMIN_OWNER 被误撤可重新登录自愈，无需额外保护。
3. **`POST /api/admin/users/:id/reset-password`**：生成 16 位随机密码（randomBytes→base64url），scrypt 哈希落库（复用 auth-util 的 derive），**清空该用户全部会话**；响应一次性返回明文密码，服务端不打日志。
4. **`POST /api/admin/users/:id/force-offline`**：DELETE 该用户 sessions，强制重新登录。
5. **`DELETE /api/admin/users/:id`**：删账号（sessions 靠 FK CASCADE 清掉）；votes/comments/reactions 的 user_id 是可空松引用，删后自动变匿名（与既有「清账号保流水」口径一致）；同样不能删自己。

## 前端

- **src/admin.tsx**：内容管理组新增「用户管理」段（lucide Users 图标）。
- **app/admin/users.tsx**（新，抄 log.tsx 的表格式骨架）：搜索框 + 每页 50 翻页；表格列：用户名、邮箱、身份（管理员徽标）、注册时间、票数、评论数、操作。操作列按行放四个按钮；自己那行全部禁用并标注「当前登录账号」。重置密码成功后弹一次性展示框（明文密码 + 「只显示这一次」警示 + 复制按钮）；删除/撤权均带 window.confirm 二次确认。
- 复用 admin.css 既有 admin-table/admin-mini/admin-badge 风格，只补少量样式。

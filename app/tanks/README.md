# 坦克斗蛐蛐 · 网站接入

入口 `/tanks.html`；主菜单第五项沿用 `PlaygroundEntry` 色块横推进出。开发使用主站 Vite，生产作为独立 HTML 构建，无比赛后端和模型调用。

## 来源与运行边界

- `provenance.json` 登记 2026-10-12 从组织者 Tank 项目复制的引擎文件及首批四份正式 bot SHA-256；后续参赛工作区程序亦登记完整 SHA-256。只复制实际依赖和十份最终 bot，不含训练报告、备份或旧阵容。
- `bots/*.js` 是逐字节保存的参赛素材，经 `?raw` 延迟加载。用户接受前端计算；这些源码会随网站公开，Git属性禁止转换 bot 换行字节。为保留登记哈希，只对登记的参赛素材排除主站风格 lint；不格式化、不优化作者策略。
- 原 `Tank` 文件不修改。网站引擎沿用 2.6.0 物理/雷达/计分，在 `core/brawl.js` 扩展可选地图、出生点、固定席位；`stage.js` 验证地图和起点，回放校验增加 stage 元数据支持。默认配置与原引擎回放比较验证。
- `worker.mjs` 为可信内置 bot 创建四个 Blob Worker，直接编译脚本文本，不使用 eval / Function，兼容现有 CSP。每次决策 500ms，启动与无响应看门狗 10s；完整计算后播放。运行异常/超时依现有规则出局，取消会终止所有 Worker，不制造结果。
- 回放 `meta.website.profile = browser-entertainment`，记录实际决策预算、所选四份作品登记信息；不向正式成绩接口写入。正式 50ms 评测环境继续保留在原 Tank 项目。

## 编辑与回放

26×26 地图、2×2 坦克。五种地形、一格/两格画笔、四向对称、每次笔画撤销、清空地形、拖放/触屏点选放置/键盘移动和旋转。身份跟随对应坦克，开场不再次打乱。自定义起点同时作为复活搜索参考。

修改地形或起点标为实验玩法。只禁止非法地形、越界、压墙、压水和重叠；不强制对称/连通，允许玩家设计困局。首次进入为空场，从可搜索坦克库选择四份不同程序；草稿以稳定作品 ID 本机自动保存。右侧八种配色跟随战斗和回放。撤销全部恢复当前基底的地形和起点，保留选手与颜色；不再提供手动布置导入导出。回放保存地图、起点、席位、版本和真实事件，导入无需运行 bot；历史 2.5/2.6 回放仍可打开。

回放加载失败显示中文错误并保留当前有效局面。选手状态与事件按当前时间轴显示，不提前泄露胜者。手动音效开关、减少动态、离开取消及页面隐藏暂停。

## 验证

`node scripts/check-tanks.mjs` 验证配置与回放规则；`npm run build:check` 后用 `node scripts/validate-tanks.mjs` 验证构建入口及真实浏览器 Worker。

主菜单回归继续用 `node scripts/validate-play-menu.mjs` 和 `node scripts/validate-menu-demo.mjs`。截图及检查结果存于忽略目录 `output/tanks/`。

新手引导以真实控件聚焦和浮层说明介绍地图、坦克库、配色、布阵、实验编辑及开始；回放另有播放、战况和保存引导。可返回、退出并恢复焦点，不改变配置。

2026-10-12本地验收：引擎15项、构建浏览器137项通过；主站菜单820项、独立菜单729项为前轮通过，本轮菜单未改；typecheck、完整lint及check构建通过。三张默认地图与一张实验地图实际运行四份登记程序，桌面/矮屏/2K/触屏/纸墨和进出过场已检查，尚未推送或上线。

## 战斗呈现

`presentation.mjs` 从记录的微步弹道与真实事件生成可重复采样的画面，子弹在两帧之间连续运动，到碰撞点消失。受击、碎片、微震、炮口与击毁提示只表达记录过的事件；胜负、命中及分数仍由原引擎确定。回放暂停保留小数进度，减少动态关闭镜头震动及额外粒子。

`node scripts/check-tank-presentation.mjs` 检查轨迹端点、短命炮弹、事件时间和确定性。开发预览 `/reference/tank-combat-review.html` 可打开实际保存的回放，比较原始离散帧、新呈现及减少动态；不运行 bot、不制造成绩。

## 模型与作品身份

坦克库分别显示作者模型和坦克作品名。新增 DeepSeek V4.1 Flash / shrike（伯劳）、GLM-5.3 / 伯劳 SHRIKE、Kimi K3 / kestrel；作者模型以用户给定的参赛目录标签登记，策略说明中的代理自报身份不作为模型定名依据。来源目录与哈希保留在 provenance.json。战斗结束的获胜标题和排名行显示模型名，布阵与交锋记录仍保留作品名。

- 作品身份以稳定id区分，作者模型可重复；每份登记包含reasoningEffort。现有astra-knife为medium、Tank26为max，新增iron-ambush / GPT-5.6 Luna、Rift Harvest / GPT-5.6 SOL、Parallax / GPT-6 Astra均为max，其余八份为high。标签记录生成作品时的思考强度，不改变比赛决策预算；坦克库/席位/结算显示并随回放保存。旧回放缺此字段时，已核实作品可用登记信息补齐。

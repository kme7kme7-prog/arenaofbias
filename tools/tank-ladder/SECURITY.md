# 上传执行边界

## 已实现

上传内容只进入私有 SQLite，不经静态目录发布，不解压、不安装依赖、不执行 shell、不加载 Node 模块。普通网页客户端不能提交比赛结果；远程计算接口只允许持有运营节点密钥的可信计算器回传。落库核对任务租约、环境和比赛清单，原子更新四名参赛版本的评级。持有节点密钥的机器属于可信边界，不能开放玩家众包计算。

Bot 在 QuickJS 的 WebAssembly 实例内解释执行。只通过 JSON 接收本席观测，返回宿主二次校验的移动/开火指令。没有传入宿主函数、Node 对象、文件、网络或其他 Bot 的上下文；禁用 Date、Promise，使用确定性随机数。异常信息不从恶意对象中读取，访客看不到源代码或堆栈。

每个 Bot 有独立 QuickJS Runtime；内存、栈、中断预算及墙钟兜底限制。每场新建 Node 子进程，清空环境变量、不继承终端/日志流、限制 V8 堆和栈，整场超时强制终止并等待退出后释放槽位。**子进程是崩溃/时限控制手段，不是 OS 权限沙箱**；Node vm 也不是这里的安全边界。WASM、QuickJS、Node 和 Windows 本身仍属于需要持续更新和监控的可信基础。

本地服务检查 Host、Origin、Sec-Fetch-Site、随机 CSRF token 和服务端身份。Cookie 为 HttpOnly/SameSite=Strict；本地 HTTP 没有 Secure，正式 HTTPS 适配必须加上。静态文件白名单、正文上限、速率/队列/日额度、HTML 转义、CSP、禁止嵌入与跨源读取都已加入。源码不通过网页 API 返回；只有独立端口的已认证计算节点能领取本场源码，连接要求 SSH 隧道或 HTTPS。详见 REMOTE-RUNNER.md。

## 为什么暂不直接公开端口

- 本地试玩身份可以重新创建，不能当作可靠账号或抗刷机制；20 次上传/120 场额度目前只用于本地演示。
- 当前已拆分独立子进程，且支持异机节点；仍未自动配置 OS 账户/Job Object/VM 隔离，WASM 内存、整体 RSS 和磁盘占用不能只靠 V8 堆上限控制。没有证明可抵抗所有恶意输入，也没有进行第三方安全审计。
- 提交者的模型名与思考强度没有自动核验，不应展示为平台认证。
- 初步匹配不是抗串通赛事系统；多账号、反复改版本重置评级、定向刷分、无尽排队需要正式账号和赛事政策。
- 数据暂未做总磁盘配额、回放保留周期和后台清理。导出的最近 60 场摘要不是灾备。

## 已选 Windows 方案的上线实施顺序

1. 用已有网站账号换取受签名、短期的提交身份；所有写入经主站校验，不把本地自助创建身份接口暴露出去。
2. 将计算器作为独立 Windows 服务，使用专用低权限账户、独立数据目录。服务账户不给主站密钥/SSH/用户资料权限；通过防火墙限制外连。使用 Job Object 或等效服务级限制覆盖进程树、总内存和 CPU。不要在有日常账号和开发凭据的桌面进程中承接公网来稿。
3. API 与计算器分离，提交队列最小权限访问；计算节点只取得本场源码和封存任务。结果用单次任务凭据回传，由主站校验；不能相信浏览器跑出的成绩。
4. 加入按真实账号的配额、待审/停赛、运营暂停开关、告警、磁盘上限、回放保留和备份；失败局留审计记录。Windows 与运行器依赖升级都经过新季/兼容计划，不热更进行中的比赛。
5. 在目标机器完成预算、异常率和耗时分布测量，再公布固定配置与赛季规则。当前本地测试和有限观测兼容检查不等于开放公网的验收。

## 本地备份与恢复

先正常停止服务，再复制整个数据目录（包括 SQLite 相关文件），不要只复制运行中的主数据库文件。恢复需同一执行环境指纹，且不要让两个进程同时占用该目录。启动锁会拒绝第二个进程；非正常退出后的 running 任务恢复为 queued，旧结果的唯一任务键防止重复结算。

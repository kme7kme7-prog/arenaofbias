# 线上 S01 投稿入口

正式入口 `/ladder.html`，使用主站账号。公开 API 是 `public-api.mjs` + remote-only `coordinator.mjs`，Linux VM 中的 i5 计算，单并发。每账号一辆主力、滚动24小时6次上传/24场排赛。操作和部署边界见 [线上排位说明](../../docs/games/tank-ladder.md)。以下为保留的本地开发说明，`server.mjs` 不作为公网服务。

# 坦克排位 · 本地试赛

可运行的上传排位原型。使用原四人 2.6.0 引擎和三张地图，不改变既有 Bot 源码，也不读取旧跑榜台的排名。

## 启动

在本目录执行（Node.js 22.13 或更新版本）：

```powershell
npm ci --ignore-scripts --no-audit --no-fund
node server.mjs
```

然后打开 <http://127.0.0.1:5472/>。安装依赖后也可双击 `start.cmd`。启动器按自身目录定位，不依赖打开终端时的路径。

协调端依赖 Show1 的 `app/tanks/engine/core`、`bots`、`provenance.json` 和回放渲染器，不能只复制这个目录。独立计算节点可用 `node package-runner.mjs` 打包，详见 [Windows 计算节点](REMOTE-RUNNER.md)。包不含 Node.js、依赖安装目录、数据库或密钥。

默认数据目录是仓库下 `.local/tank-ladder`。可通过 `TANK_LADDER_DATA` 指定另一个绝对路径，通过 `TANK_LADDER_PORT` 改端口。仅监听 127.0.0.1，不提供公网监听开关。

## 能做什么

- 首次导入现有 22 份作品，逐份核对登记的 SHA-256；不改原文件、不虚构成绩。
- 上传不超过 256 KiB 的单文件 `bot.js`，保存版本后在 QuickJS/WASM 内检查。名字、生成模型、思考强度分别填写；后两者属于提交者声明。
- 同一账号可保存多件作品和多个不可变版本，但仅 1 辆主力同时上榜。账号第一份通过检查的作品自动参赛；其余作品/版本保持候选，需手动切换主力。服务端事务与数据库唯一约束共同限制名额，旧成绩保留在原版本。现有坦克库是独立基准选手，不占投稿账号名额。
- 切换后已排定的比赛仍使用封存的旧版本完成，成绩归原版本；之后新创建的匹配只选当前主力。切回旧版本可继续原成绩，不复制、清空或转移分数。上一批未结束时，仍需完成或取消待赛任务后再安排下一批。
- 每次安排 12 场：三图，每图同一随机种子轮换四席。匹配相近评级并加入随机探索；批次在创建时封存对手、代码版本、地图、种子、座位和执行环境指纹。
- 默认后台顺序调度，每场独立子进程执行；关网页继续计算。也支持受认证的远程 Windows 计算节点，1–8 并发槽位、180 秒任务租约及过期重领。暂停/取消仅影响自己未开始的场次，正在进行的一场会完成。停服务时未完成局不计分，重启重新计算同一封存任务。
- OpenSkill 保守排位分、并列胜率、场均击杀、总场数；完成 12 场后进入正式排序。档案显示平均得分、异常次数和代码指纹。
- 完整回放、暂停/拖动/倍速、逐场 JSON 下载。总导出包含当前参赛版本和最近 60 场摘要，明确不是全部历史或源代码备份。
- 页面使用自然滚动，不设置榜单或队列内部滚动框。榜单、记录与队列每页 6 条，作品每页 4 件；旧版本主动展开，当前主力和最新上传保持可见。小屏榜单改为保留全部统计的卡片排版。

以上是本地试玩流程。公开 S01 已接主站账号与 i5 远程计算，空闲时自动排赛、优先场次少的主力；详见 `../../docs/games/tank-ladder.md`。本地 `server.mjs` 保持手动模式。

## 本赛季执行配置

用户已确定采用 **Windows + QuickJS/WASM**，作为独立新赛季，不继承原 Node/V8 排名。当前是定标期配置：

| 项目 | 当前配置 |
| --- | --- |
| 引擎 | 四人 2.6.0，三条命、两格装甲、600 tick |
| 地图 | 十字猎场 / 四桥孤岛 / 环形废墟 |
| JS | quickjs-emscripten 0.32.0，锁定依赖 |
| Bot 内存 / 栈 | 64 MiB / 64 KiB |
| 每步预算 | 4,000 次 QuickJS 中断检查，2 秒墙钟兜底 |
| 整场兜底 | 120 秒，Worker 堆上限 192 MiB |
| 上传 / 对局额度 | 每试玩身份每天 20 次 / 120 场 |
| 评级 | OpenSkill 5.0.1，Weng-Lin，tau=0 |

中断检查次数不等于 CPU 指令数，也不等于原 V8 的 50 ms；墙钟兜底仍受机器负载影响。上线前应在实际 Windows 计算机上完成更大样本定标，再冻结赛季。`calibrate.mjs` 提供有限观测样本的耗时报告，不代替整场压力验证。

显示分数为 `round(1000 + 40 × (mu - 3 × sigma))`；胜者并列时平分胜场。评级采用引擎最终名次，Bot 异常/超预算沿用引擎出局规则；整场基础设施失败或四份 Bot 全部失败不计分。新版本从先验开始，不转移旧版分数。

SQLite 存储原子结算和压缩回放。同一任务重复结算不会重复加分。数据库记录引擎、执行器、调度/结算代码、预算和依赖的指纹；不匹配时拒绝复用，需新数据目录。不要手改指纹绕过校验。服务启动后不要热改运行器；先停止、使用新数据目录，再启动新季。

## 验证

```powershell
npm test
# 从 Show1 根目录执行，使用独立临时数据，真实运行 12 场
node scripts/validate-tank-ladder.mjs
# 布局、分页、六档视口；历史回放仅作为本机浏览器展示样本
node scripts/validate-tank-ladder-layout.mjs
# 真实上传两件作品并切换主力，不计算对局
node scripts/validate-tank-ladder-slot.mjs
# 从本目录执行，生成有限样本的兼容与预算报告
node calibrate.mjs
```

测试覆盖隔离/死循环/递归/内存/恶意 getter、权限/CSRF/来源/大小限制、不可变版本、座位轮换、幂等结算与恢复、环境变更拒绝。原件兼容测试调用现有 Node 跑榜适配器，仅用于已登记的可信原件；上传服务不使用 Node vm 执行来稿。

浏览器检查生成纸墨、320–2560px 视口和真实回放截图；证据在 `.local/tank-ladder-qa/`。全量复现依赖根目录的 Playwright 测试工具，不属于正式服务器依赖。

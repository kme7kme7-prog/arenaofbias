## 001–009 · 早期视觉与规则基线

- 001 · 视觉与动效走游戏式体验，不接受泛滥的极简 AI 产品样式。
- 002 · 首页纸灰绿 + 深墨 + 酸性黄，主入口深色底亮字；厚重立体被否（唯一例外 013）。
- 003 · 入场退焦与遮挡：当前作品放大居中、非当前统一退焦（opacity/blur/饱和度一致）并保持可见，由放大作品自然遮挡重叠区；不给 contender 加不对称 filter。
- 004 · VS 装饰限制在中央间隙；锁定提示在内部呈现支持率，不用悬空进度条。
- 005 · 结果页不使用摘要小卡片、不做频道面板化。
- 006 · 评论按提示词聚合；旧 API 的 side 字段仅为兼容保留、不能推断立场；将来做按模型的评论/投票必须存 modelId（左右会随机交换，无阵营语义）。
- 007 · 评论需登录才能发表；历史无主评论显示「匿名观测员 #XXXX」。
- 008 · A/B 只是展示位置：抽组随机分配左右；换组优先避开刚看过的组合。
- 009 · `isDemo` 样例不计模型数、不参与配对与随机竞技场，仅预览页可见。

## 039–046 · 服务端校验、数据入库、后台与匹配

- 039 · 投票写入前服务端核对票面（rid 真实、非 demo、属本题、与 mid 一致，不符 400）；同 UUID 回读比对全部字段，跨对局重放或票面不符按 409 `code:'id'` 拒绝。榜单聚合的阵容过滤保留（兜底已下架作品的历史票）。
- 040 · 作品从「编译进代码的 JSON」迁入 SQLite `works` 表（content 存 ResultContent 同构 JSON、published 发布开关、`PRAGMA user_version` 驱动迁移）；前端 `/api/works` 拉到为准、拉不到回退内置。被否：独立后台项目、MySQL。
- 041 · 后台是**同仓库双应用**（`admin.html` → `src/admin.tsx` 独立构建，共享 lib/ 与 /api）；管理员 = `users.role='admin'`，首位 `ADMIN_OWNER` 引导；`/api/admin/*` 未登录 401、非管理员 404；不接第三方统计。
- 042 · dev 登录自动授予管理员；访客统计由前端 `POST /api/track` 上报（跨源 403、失败静默）；dev「清空重投」只删 dev 自己的真实票，不绕过去重。
- 043 · 作品目录 = `WORKS_DIR`（默认 `data/works`，gitignore 内，大文件永不进 git）；`register:works` 解析「标题，模型名.html」入库。
- 044 · 作品管理：发布开关即时生效；标题/模型名可编辑、**model_id 不可改**；**不提供删除**（投票流水引用作品）——此条后由 2026-09-25「零票可删」放宽。收件箱 `data/inbox` → 后台登记搬进作品库、默认草稿；多文件作品 = 整个文件夹（根目录 index.html）；同模型重复登记自动让位 -2/-3；只收单段文件名（防路径穿越）。
- 045 · 题库入库 `prompts` 表（前端启动拉取、失败回退种子）；后台可下架/新增/编辑；**下架 = 前台完全隐藏**（不显示、不进随机池、不可写入）但**历史票保留**；**文案允许自由改**（不影响已有投票）；不提供删除。
- 046 · 轻量匹配（不做强匹配）：声望分由 votes 全量重放（基准 1200 / K=32）；配对每 150 分一档、90% 同档 + 10% 全池保底；分差 >400 熔断重抽 ≤2 次；占位模式纯随机；拉不到声望分退回均匀随机。冷启动等价均匀随机是设计预期。来源：用户「不能老让垃圾的模型匹配到最强的模型……不要搞太强的 只要轻微的」。

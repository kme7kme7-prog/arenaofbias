## 本轮目标

用户提出匹配问题：「不能老让垃圾的模型匹配到最强的模型……加个 elo 分之类的东西，但不要搞太强的匹配机制，只要轻微的」。方案先说后做（软性分档 + 保底随机 + 处刑局熔断，明确不做天梯式撮合及其榜单污染问题），用户拍板「动工吧」。

## 改动

- **`lib/matchmaking.ts`（新）**：`pickMatchedMatchup`——声望分每 150 分一档、90% 同档随机 + 10% 全池保底、分差 >400 熔断重抽 ≤2 次（重抽仍超限照常返回）、上轮作品回避叠加；`MATCH_CONFIG` 参数集中（baseRating/tierWidth/sameTierRate/blowoutGap/rerollLimit）；`computeRatings` 全量流水重放简易 Elo（基准 1200/K=32）。
- **`lib/ratings.ts`（新）**：启动拉取 `GET /api/ratings` 的小 store；`currentRatings()` 未就绪/失败返回空对象——匹配层按基础分兜底（=均匀随机，站点不劣化）。
- **`server/index.js`**：`GET /api/ratings` 公开接口——votes 表全量重放（与 computeRatings 同公式同口径，validate-matchmaking 逐位比对验证）；无增量状态，dev 清票后自然重算。
- **`lib/placeholder.ts`**：`currentMatchup` 分流——占位模式走旧 `pickMatchup`（纯随机，占位作品无真实票），真实模式走 `pickMatchedMatchup(currentResults(), currentRatings(), previous)`。
- **`src/main.tsx`**：启动 `loadRatings()`。
- **`scripts/validate-matchmaking.mjs`（新，npm run validate:matchmaking）** + package.json 挂载。

## 决策

- 决策 046：声望分是内部暗分，与前台榜单解耦（同公式独立重放）——匹配机制不污染榜单，榜单也不直接驱动匹配；冷启动期（分差未拉开）行为等价均匀随机是设计预期。

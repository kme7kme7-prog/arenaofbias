# 产品当前行为

总入口 `arenaofbias.icu` 的左右色块点击后铺满，再进入竞技场或展览馆。带入口标记的目标页保持同色遮罩，首屏准备好才揭幕；错误或 25 秒等待超时显示加载失败、重试和返回入口。普通直接访问保持原启动方式。竞技场整站画面默认使用 80% 站内缩放（浏览器设置保持 100% 即可）。

本文描述当前已实现的产品行为：用户能感知到的规则与语义。长期愿景见 `README.md`；实现细节（字段、函数、文件结构）见 `docs/ARCHITECTURE.md`。

## 用户路径

- 首页默认新版，经典 / 新版 / 对决版的切换位于开发者面板，浏览器记住选择。新版精简重复口号与装饰，保留品牌、一句说明、开始评测与随机入口，以及图像 / 文字 / 网页作品示例切换。主按钮进入玩法菜单，保留题库、榜单、语言与账号入口，投稿入口前往 Gallery 选题。全站支持纸 / 墨主题：纸面保留既有配色，墨色以橙色强调，主题选择本机持久化并遵守减少动态效果设置。图片为早期遗留演示展陈；网站主要对比前端、网页等作品，不做生图测评（决策 066）。

- 首页 `#home`（含空 hash 与任何未识别的 hash）的视觉重心是进入**玩法菜单** `#play` 的主按钮（决策 023）；新版首页的随机入场位于主按钮下面，提示词库与偏好榜在下方并排的「继续探索」区，页眉提供展览馆、投稿及语言、主题、账号入口。全站页头品牌字标为 MiSans 双字重样式（移植自空间版，决策 027）。
- 首次进首页弹一次**内测提示弹窗**（决策 110）：标题「内测版」，正文三句——「这个小游戏网站还在小范围内测。」「玩法与榜单功能大致做完了，剩下还在打磨，预计有特别多bug。」「现在投票都会被计入；如果遇到哪里不对劲，马上发给我。」，按钮「知道了」。看过与否记在 localStorage（`aob-beta-notice`），文案改版时升版本号让老访客重看。
- 玩法菜单 `#play`（仪器档案风列表）列出四种玩法（名称暂定）：**正式测评**（前往展览馆 `https://gallery.arenaofbias.icu/#/arena`，行内提示将跳转到展览馆参与盲测）、**娱乐测评**（进入随机竞技场，即当前竞技场流程）、**特别赛·鹈鹕大乱斗**（独立页 `#event`，菜单入口暂锁、不可点击并标注「暂未完成」；当前为占位页，轮换规则与独立榜单筹备中，见决策 026 与想法 P06）、**模一把**（独立页 `#guess`，Wordle 式每日猜模型，决策 057）。
- **模一把**（`#guess`，决策 057/060/064）：进游戏先选模式——**每日一题**（全世界同一道题，从简单+标准池出，8 次机会，记战绩可分享）或**练习模式**（三档难度随机出题、不限次、不计战绩）。对局只存浏览器本地，无需登录；每日一题结束上报一条结果，2026-09-25 起登录用户记名（user_id，供后台按人统计），游客与此前历史均匿名。完整规则（七属性口径、反馈阈值、每日答案派生、数据集维护契约）见 `docs/games/guess.md`。
- 提示词库支持搜索提示词、按作品类型筛选，并显示每题的模型数与结果数（均不含演示样例）；档案右下按钮统一显示"前往展览馆 / 浏览提示词与作品"，链接到展览馆题库 `https://gallery.arenaofbias.icu/#/questions`。左侧目录每页最多 8 题，提供前后页与页码；搜索和分类覆盖全部题目并重置到第一页，右侧前后题与方向键跨页时目录同步翻页。共享题目含长短两份原文时，题库和无结果预览提供切换按钮，两版属于同一题号。
- 每个提示词只有一个竞技场地址：`#arena/{promptId}`。直接打开、刷新、前进后退都以地址中的题号为准。
- 打开 `#arena/{promptId}` 时：有可比较结果则进入竞技场；没有可比较结果则进入提示词预览页（展示提示词全文；有 HTML 样例时可预览、独立打开或下载）；题号不存在则显示引导回提示词库的页面。
- 旧地址 `#arena` 与快捷地址 `#random` 自动跳转到随机竞技场。

## 数据归属

概念模型分四层：

- **Prompt（提示词）**：比较的共同题目与边界。
- **ModelResult（模型结果）**：一份作品，唯一 id，归属某提示词，记录生成它的 modelId / modelName。
- **Arena（竞技场）**：按提示词组织，同题结果才互相比。
- **Matchup（当前对局）**：一次抽出的两份结果。

同一模型可在一个提示词下有多份结果，也可出现在多个提示词下。结果不属于固定的 A/B 阵营：A/B 只是当前展示位置，每次抽组随机排列（见决策 008）。

作品数据存服务端 SQLite works 表（决策 040）：页面打开时拉取已发布作品清单，新登记的作品默认未发布、对访客不可见；拉取失败时站点回退到内置清单，行为不变。

题库由共享后端 `/api/prompts` 提供：正式题目来自共用数据包，历史题保留既有编号、名称和管理配置。页面打开时拉取已发布题目，后台下架的题前台完全隐藏（题库页不显示、竞技场地址落"未就绪"、不进随机池）；拉取失败时回退内置题库。题目类型（文字/网页）决定偏好榜赛道归属。长短原文属于同一道题，不登记成两个编号；新增题目尚无可比较作品时显示提示词预览。

作品按内容的四种形态呈现，用户可见差异如下：`image` 直接展示图片（当前题库未使用）；`text` 是文章卡片，入场时自动滚动巡览全文；`web` 卡片态为静态页面，展开 Dialog 后可交互点击；`html` 在只允许脚本的沙盒 iframe 中运行，卡片态不可交互，展开后可交互。

## 抽取规则

1. 只在同一提示词内配对。
2. 两份结果必须来自不同模型（modelId）；isDemo 样例不参与配对。抽取是**两级**的（决策 097）：先等概率抽两个不同模型，再各从该模型在本地的作品里随机抽一件——对局均匀分布在模型对上，作品多的模型不因此获得更高出场率；投票加成的永远是模型本身，与抽中哪件作品无关。同一模型的多件作品（如 001 的 GPT-6 Astra 六份）在 2026-09-19 身份统一后共用一个 modelId：显示名全站唯一对应一个模型，`-0xbqp`、`-low`、日期哈希等变体尾巴全部剥离合并（唯一保留的是「DeepSeek V4 Pro（灰测0821凌晨）」）；合并产生的同模型内战历史自票已随迁移删除。
3. 真实模式的抽取带**软性匹配**（决策 046）：每个模型有一个由该测评范围内历史投票算出的内部声望分（用户不可见，与榜单分数独立）；抽对局时优先在声望分相近的模型之间选择（90% 同档随机 + 10% 全池随机保底），双方分差过大的「处刑局」会尽量重抽避开（最多两次，避开不了照常进行）。声望分差距尚未拉开时（新站、票少），行为与均匀随机一致。池内抽组合还带**冷门优先**（决策 109）：出场次数越少的模型，其组合被抽中的权重越高（权重 = 1/(1+双方中较少出场数)），新模型能更快积累场次；全部零出场时退化为均匀随机。
4. "换一组"时，上一轮出场的两份作品下一轮都不出现（防身份泄漏：已揭晓的作品若再次出场会被认出，盲测失效）；无可避开时（如只剩一组可配）回退到全量组合，且始终留在当前题。软性匹配叠加在其上。
5. 只有一组可比较时，按钮明确显示"重新比较本提示词"，不假装还有更多作品。
6. "随机换个竞技场"才切换题目；存在其他可用竞技场时避开当前题。
7. 不足两个不同模型的题在库中展示但不提供比较入口，也不参与随机入场与随机换场；全场无可比较时随机入口退回提示词库。
8. 占位模式（开发者演示）不走软性匹配，维持纯随机——占位作品没有真实投票，声望分对它无意义。

## 场内状态

竞技场以作品区为主体，题号、题名、完整提示词按钮和模式标签统一对齐；提示词展开占单独整行。重复步骤、旁白与 system-footer 已移除，题目详情收在可展开的背景说明中。文字作品随内容展开，固定画布保留原校准；桌面与窄屏的继续按钮均保留就绪门控。

- 娱乐测评的继续入口为并排双按钮：左「换个题库继续」随机去其他可比较题目（排除当前题），右「同一题库继续」保留当前题目并重抽作品，沿用既有匹配与上轮作品回避。手机保持两列，右侧酸黄主按钮；N 键仍是同题换组。无其他可比较题目时左侧禁用并说明；同题只有一组时提示将重新比较本组。加载/切换期间共享防重入锁。正式测评复用同样的双继续入口，换题后仍留在正式模式（2026-09-23）。

- 进竞技场（玩法菜单娱乐/正式、首页随机入场、题库「进入竞技场」、事件页起源之题）统一先起整屏纸幕并钉在盖满位当加载中间态：牌面带题号标题与「正在接入试验场」、A/B 连线逐侧报就绪进度，双侧作品完全就绪才扫出展开（决策 099）；场内「换个题库继续」同口径（决策 096）。未就绪的题从题库进落预览页，不钉幕。
- 过场与换题纸条的时间轴都是帧时（决策 100）：单帧推进封顶，主线程饱和掉帧时原地冻住、恢复后从冻点续播，不按墙钟追进度跳段；门释放后帧率没恢复（连续 3 帧间隔 ≤250ms）纸幕继续钉着等，恢复才起扫；扫出中途遇掉帧原地冻、不回弹。文字纸条等纸幕真进扫出段才错峰揭开，与作品揭幕落在同一窗口。
- 视角校准（决策 102、104、105）：three.js 场景作品可在后台「视角校准」里拖到好机位存进作品元数据；竞技场加载该作品时服务端注入桥、在首帧后套用保存视角——观众开箱就是调好的构图，原始 HTML 不改动。未校准作品的响应与改造前逐字节一致。三条接入途径：全局 UMD、importmap（指 CDN 或作品自带本地 three 皆可）、以及作品在构造相机时自己上报一句（three 整库内联的作品走这条，007 黑洞 34 件已全部可校准）。弹窗探测会等到 20 秒，超时后仍继续等——慢启动的作品（等 CDN、等着色器编译）上报后自动接管。没有自报口的打包作品（当前是多数体素作品）相机钩不到，弹窗会明示不适用、请用画布校准。
- 一次对局经历：载入 →（若经菜单/随机入场，先等过场层完全离场）→ 作品揭幕 → A/B 依次聚焦（只有内容真实溢出才自动滚动）→ 投票 → 锁定反馈 → 身份揭晓 → 两侧判断与反应 → 提示词及结果操作。评论区当前暂时隐藏（2026-10-01），后端接口与既有评论保留。入场不再有「本轮开始」横幅（决策 095），只剩「加载过场 → 作品揭幕」两拍：加载过场一直压着舞台，直到**两侧作品都完全就绪**才收场并揭幕淡入——不再按时钟放行，慢作品宁可多等也不给半加载画面。作品就绪口径：文档解析完且脚本已执行；注入了 `data-aob-probe` 探针的作品还要等它上报渲染循环首帧（postMessage 握手）——场景型作品不放到「脚本跑着、画面还没画」的中间态。等待期作品区整体隐藏，底部两条投票条改成逐侧进度指示（决策 095）：未就绪的一侧退成空心槽 + 自己的队色光带往复扫，就绪即填回实心队色，A 红 B 蓝各报各的。死等满 8 秒仍未就绪的，不替用户揭幕，只在过场里给出「跳过此题」出口（正式模式且本题另有组合时标为「换一组作品」）。文字/模板/图片类作品视为即时就绪；空格跳过仍然可用。作品秒回时首次入场仍约 6 秒到可投、重播约 5.2 秒（节拍不变，揭幕段从余量里扣）；作品加载慢时总时长只顺延不空等。重播不再重复横幅。入场动画只走合成器属性（不用会整屏重绘的 `clip-path`），主线程被重作品的渲染循环占满时也不会被挤掉。动画只负责呈现，不会因掉帧或标签页调度延迟投票解锁；结果内容按信息层级依次进入。换组、重播、切换模式时经过转场回到入场。
- 娱乐测评选择后立即弹出本题当前两份作品的选择反馈牌：锁定阶段先以红蓝脉冲表示正在汇总，提交结束后读取已落库票数并无缝填入；票数按当前作品 id 对应左右，红蓝条表示左右选择的比例（不含平局），平局单列。反馈从点击起约 1.9 秒内完成进场、展示与退场，也可手动关闭；零票不伪造比例，占位模式不显示真实人数。重播、换题取消旧请求，正式测评不展示该面板；原模型名字解密特效保留。
- 底部操作行的「逐个巡览」开关（桌面可选项，默认关，浏览器记住选择；窄屏不提供）关闭后，入场只保留作品揭幕一拍，不再依次放大两份作品，直接开放投票；入场也可随时跳过。A / D 键投左 / 右，S 键无法抉择，N 键换一组，空格跳过入场。
- 娱乐测评点「换个题库继续」或「随机换个竞技场」时，双页纸幕只覆盖场内区域（对比信息行 → 作品区 → 操作行）：纸色半页从左右合拢，展示下一题题名与题号、红蓝细线，420ms 盖满切题；盖满后纸幕**钉住等新一场两侧作品完全就绪**（就绪口径同入场门控，决策 096）——牌面兼任加载屏，「正在接入试验场」注记呼吸显形、A/B 连线按侧填成队色报进度；就绪后纸幕向上下打开、结束后按入场时间轴展开，不再出现独立的加载屏。慢加载不自动放幕，15 秒后在幕内提供返回提示词库出口；作品就绪与显示完成后再退场，不露出独立加载屏。直接深链无上级纸幕时保留跳过出口。过场随场内区域一起滚动，含顶部场次标记、淡点阵与 A/B 红蓝连线；区域外的命题栏、顶栏等按原样即时更新。正式测评同题继续走内部切换幕，换题继续复用上述双页纸幕并保持正式模式。
- 除左右两个选择外有第三个按钮「无法抉择」（决策 048）：不是跳过，而是**记为平局**——作为一票落库，榜单与声望分重放时双方各得半分（胜场/负场不计、记平局数，胜率分母含平局）；平局同样占用对局去重（投过平局不能再对同一对改投胜负，反之亦然）。揭晓时两侧都显示「平局」；评论区当前暂时隐藏。
- 进入竞技场、换题、同题换组与重播时自动定位到本轮命题（距视口顶部约 12px）；正常为平滑滚动，减少动态效果时直接定位。有效竞技场换题不会先全局归顶再二次定位，只执行一次场内定位；投票、揭晓与评论刷新不触发定位。
- 长提示词（超过 90 字符）在场内默认显示题目名，可展开完整内容；较矮的桌面视口收紧顶部信息，作品高度按对比区宽度计算（340–540px），不足一屏时允许整页滚动，不随揭晓缩小。选中作品底边扫动确认、结果标签依次出现，减少动态效果设置下直接呈现。
- 换组、重播或切换模式都会清除当前选择并重新走一遍流程。
- 正式地址也检查管理员资格，退出登录后返回玩法菜单；占位模式必须先关闭才能进行正式评审。
- 两种玩法共用竞技场：**娱乐测评**（`#arena/{promptId}`）——身份隐藏，做出选择后才揭晓（决策 024）；**正式测评**（`#formal/{promptId}`，需资格）——任何环节都不揭示模型名称，投票后也没有评论区，选择以 formal 模式落库（决策 028）。原全程公开身份的「娱乐站队」已废除（reducer 内部的 mode 字段保留）。
- 投票落库（真实模式）：选择即向服务端提交一票（记录对局双方的作品 id 与模型 id、投票时的模式）；娱乐与正式的评审数据独立：娱乐票只计入娱乐榜，正式票只计入正式榜；匹配声望分、出场次数和六维画像按相同范围分别计算。榜单可切换两种范围，正式结果区直达正式榜（2026-09-23 决策替代旧混榜口径）。揭晓区按结果显示"你的选择已计入偏好榜 / 登录后会计入（附登录入口）/ 这一对作品你已经投过票了 / 暂时没有记上"。
- 投票去重：同一账号在每种测评范围内对同一对作品只计一票（与胜负和左右位置无关）；娱乐投过仍可正式评审，历史 party 与 blind 同属娱乐范围；同一模型换作品或换对手可以再投。
- 揭晓后的「你的态度」反应（点赞/点踩/大笑，决策 054）：当前共享后端为一人一题一模型一槽，切换覆盖、同键取消。**本地优先**：点击即时显示，换组、离页或关页再同步最终意图；队列按账号、题目与模型隔离，同步期间的新操作保留。发送前核对当前账号，切号后丢弃旧账号意图；失败留待重试。旧分支的作品级评价 API 不在本轮启用。
- 占位模式下投票只写入本地 localStorage（不入库），提示"已写入本地演示数据 · 占位模式"。
- 音效默认关闭，可手动开启；支持全屏与 reduced-motion 降级。

## 账号、评论与投票

- 注册账号为 2–24 位文字、数字、下划线或连字符（不区分大小写），密码 8–128 字符；登录状态保留 30 天，窗口重新聚焦时自动刷新会话。
- 注册必填邮箱（2026-10-01）：匿名发送注册验证码后，以账号、密码、邮箱与验证码一次提交注册，成功时邮箱已验证；登录后可在「账号绑定」添加或更换邮箱。验证码 10 分钟有效、一次性、错 5 次作废，会员视图只显示打码邮箱。邮箱可用于重置密码，成功后所有设备重新登录；找回发码响应不会透露账号是否存在或已绑定邮箱。邮箱不作为登录名。Cloudflare Turnstile 守注册/绑定/找回发码，注册提交只使用邮箱验证码；未配置两把密钥时关闭。
- 注册、账号绑定和找回密码发送验证码后，提示未收到时检查垃圾邮件箱；该提醒提供中英文，找回密码的发送提示也随界面语言翻译。
- 发表评论、计入投票与表态都必须登录并绑定已验证邮箱：未登录或旧账号未绑定邮箱仍可看作品、选择和揭晓，选择不计入榜单。揭晓区分别提供登录或绑定入口；后端明确返回未计票时，不显示计票成功或写入本地演示票。未绑定账号点击表态先引导绑定，不改变计数；服务端拒绝的表态不会在绑定后自动补发。
- 开发者面板（右下角 "dev"）只对管理员 `kme7` 显示，其余账号与游客一律不渲染入口（决策 110）。面板明确提示管理员可直接参加正式测评，并提供前往玩法菜单的入口，无需退出或切换账号；原不可达的 dev 免登录/清票控件已移除。退出账号时面板完整卸载，重新登录后可以正常开合。`/api/auth/dev` 仍仅用于本机开发/验证，线上未开放。
- 评论区当前暂时隐藏，玩法菜单同步去掉赛后评论说明，首页步骤改为「03 看揭晓」。后端评论接口与已有评论保留；下述评论布局与身份规则为隐藏前已实现行为，恢复显示需另行决定。
- 揭晓后两份作品保持投票前的展示尺寸；结果操作与评论区依次向下延伸。桌面评论输入与列表分两列，手机纵向排列，长评论随整页滚动（决策 037）。
- 已登录评论显示账号名；历史无主评论显示"匿名观测员 #XXXX"（编号取自评论 id 前四位）。
- 评论的 side（左右）字段仅为旧 API 兼容保留，不代表支持哪个模型，前台不展示阵营（见决策 006）。
- 单条评论 1–280 字；每 IP 每分钟最多 10 条（投票共用同一限流）。

## 扩充内容的产品层约束

- 新提示词使用三位数字 id；新结果的 id 必须唯一，promptId 指向已存在的题。
- modelId 必须稳定：同一模型在不同题、不同结果间使用同一 modelId，否则会被误认为多个模型；只有不同 modelId 的结果才成对。
- isDemo 样例的语义固定：不计模型数、不参与配对与随机竞技场，仅预览可见（见决策 009）。
- 正式题目在共用数据包中登记稳定 arenaId，由共享后端映射到竞技场编号；评论与投票的题目校验由共享后端执行，不按本仓旧服务的静态题号白名单收录。
- 只补齐两个不同模型的结果后，原预览页地址自动变为竞技场，无需改路由。
- 具体操作步骤见 `docs/ARCHITECTURE.md`。

## 偏好榜

- 地址 `#rank`，入口在首页（"看看偏好榜"）与竞技场揭晓区（"看看偏好榜 ↗"）。
- 榜单按模型聚合，分综合 / 写作（text 题）/ 网页（web 题）三个赛道；行内显示偏好评分（占位口径的简易 Elo，基准 1200、K=32）与参与比较次数。
- 少于 30 场的模型带"暂定"徽章；点击模型打开右侧档案卡：六维画像（视觉设计 / 空间营造 / 动态表现 / 文字表达 / 思辨推理 / 创意构思）、胜/负/胜率、题目覆盖。六维画像按真实投票重放得出：每道题配置一组维度权重（`prompts` 表 `weights` 列，后台题目管理可调，决策 093），用户仍只选喜欢哪一边，一票的分量按该题权重落到各维度（分维 Elo，基准 50、平局各半）；权重为 0 的维度不因该题变动，停在基准值。权重是重放参数——调整即时重算该题全部历史票。
- 榜单口径可切换：默认为「娱乐测评榜」，切换后为「正式测评榜」，两者票数、Elo 与六维画像独立（2026-09-23）。开关只在真实数据下出现；占位票只计娱乐演示口径。
- 投票来源：真实模式请求共享后端 `/api/show1/leaderboard`，按范围与赛道消费聚合榜单、六维画像与题目覆盖；含 loading 与拉取失败态，"重播入场"会重新请求，失败不回退下载逐票流水。占位模式读本地占位投票（竞技场亲手投的票 + 开发者面板生成的票），头部标注 PLACEHOLDER DATA。
- 票面在服务端按作品清单核对（伪造 rid、rid 与题号或模型不符、演示样例一律 400 拒收）；指向当前阵容之外模型的历史票（已下架作品）在聚合时被过滤，不进入榜单。
- 竞技场内投出的票实时计入：真实模式入库（登录后），占位模式写本地。

### 迁移前内部后台（`/admin.html`，历史参考）

下面记录本仓保留的旧双入口实现，不能作为现行馆藏登记、注册邮箱或管理员权限的操作规范。

- 同仓库双应用的内部工作台，朴素风格与主站视觉互不掺和；仅管理员可见（未登录/非管理员呈现 404 视图，不泄露后台存在）。dev 一键登录即管理员（决策 042）。已开放：仪表盘、数据流水、**作品管理**、**收件箱**、**题目管理**、**用户管理**；活动管理为诚实占位（明确标注未开放，决策 040/044/045）。
- 后台工作台按总览/内容管理/玩法分组，桌面侧栏可收起，舒适/紧凑密度保存在本机。仪表盘提供真实统计、手动刷新和内容流程入口，未发布作品可直达草稿筛选；收件箱指引可展开，数据流水提供投票/评论/注册/模一把四类页签、搜索按钮与每页 50 条的翻页（上一页/下一页，页脚显示第几页与总条数，换标签或搜索回到第一页；模一把页签登录用户显示用户名，游客与历史记录显示「游客」）。小屏导航横向滚动、宽表格在内容区滚动。
- **作品管理**（决策 044）：全部作品（含草稿与演示样例）按题号、发布状态、关键字筛选与搜索，每行显示票数。**发布/下架按钮**点击即时写库：公开端 `/api/works` 只吐已发布作品，前台刷新后生效；下架不影响已计入的票。标题与模型名（显示名）可编辑；模型 ID 不可改（榜单按它归组，票面存的是模型 ID）。预览直开作品文件，草稿也能看。**删除（2026-09-25 放宽「一律不删」）**：只对**零票**作品可用（服务端硬校验，有票返回 400 并提示下架）——删除会连同作品文件/目录一起清掉，不可恢复，供清理误传件与测试件；有票的作品因历史票引用仍只能下架。**对比测试（决策 101）**：行左侧复选框勾两份同题已发布作品（先勾的落 A 侧），选择条「进入竞技场对比 ↗」直达该题竞技场并排加载这两份，直观核对画布校准效果；测试对局期间场内挂「测试对局 · 投票不落库」徽标，投票流程照走但票不写库，榜单不被测试票污染；草稿不可勾（前台没有这份作品）。
- **收件箱**（决策 044；2026-09-25 改版）：作品登记的入口，卡片式布局。可直接把 .html（网页作品）/.txt/.md（文字作品）拖进上传区或点选上传（单文件 ≤8MB，重名询问覆盖）；多文件作品仍整个文件夹放进服务器目录 `data/inbox/`（根目录须有 index.html）。每张卡片带预览（网页作品缩略渲染、文字作品开头摘录+全文展开），确认标题、模型名、题目后登记：单文件按「标题，模型名.后缀」自动带出，可改；模型名输入自动补全现有模型（选中 = 复用其 modelId 与规范显示名），无匹配则登记时创建新模型（下拉明示）。文字作品一文件一作品、空行分段、纯库内存储，登记成功后源文件删除；网页作品登记即把文件搬进作品库。默认草稿，可勾选「登记后立即发布」；题目选择记住上一次。同一模型重复登记自动让位（-2、-3……）。不认识的文件不提供登记，任何条目都可直接从收件箱删除。题目下拉含草稿题——先加题、再登记作品、检查后上架是正常流程。
- **用户管理**（2026-09-25）：已注册账号清单（用户名、邮箱及验证状态、身份徽标、注册时间、票数、评论数），按用户名/邮箱搜索、每页 50 条翻页；**点用户名打开详情弹窗**——模一把战绩汇总（完成局数/胜率/胜局平均步数，含逐局记录）与最近投票（20 条）、最近评论（20 条）。四个账号级操作，均带二次确认：**设为管理员/撤权**、**重置密码**（生成 16 位随机密码，弹窗一次性展示+复制，原密码立即失效、该账号全部会话被清）、**强制下线**（清全部会话）、**删除账号**（不可恢复；其投票与评论保留、作者显示为匿名）。当前登录账号不能在列表里操作自己（服务端硬校验），自己的资料走右上角头像的账号弹窗。
- **题目管理**（决策 045）：全部题目（含下架）列表，每题显示类型、作品数、票数与上下架滑块。**新增题目**：编号自动往下排（008 起），填类型（文字→写作榜、网页→网页榜、图像预留）、名称、提示词全文与题库页展示文案，默认存草稿（新题通常先去收件箱登记作品）。**编辑**：文案自由改，已上架题会提醒「修改不影响已有投票」。**下架 = 前台完全隐藏**：题库页不显示、竞技场地址落"未就绪"、不进随机池；历史票保留在榜单。不提供删除（作品与投票流水引用题目）。
- 登记后的作品立即可经 `/works/...` 直访预览；是否进入竞技场配对只由发布开关决定，题目是否可见只由题目上下架决定。

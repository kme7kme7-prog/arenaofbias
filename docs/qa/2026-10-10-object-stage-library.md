# 完整公开 3D 库 · 本地展台验收

本轮仅将线上公开作品快照接到 5446/5447 本地展台，供用户先体验。主站共用主页和「娱乐测评」入口尚未改动；玩法名暂定「随心玩」。无提交、推送或发布。

## 覆盖范围

- 公开 API 快照：62 题、1156 件作品。
- 按「建模 / 3D 场景 / 物理模拟」分类纳入 37 题、682 件公开非演示作品；物理模拟中也有 SVG 作品。文字与静态网页继续分区。
- 21 题满足至少十件、可跨模型配对；16 题显示收集进度并保持禁用，直达 URL 不能绕过门槛。
- 682 件作品的 1743 个原始文件均通过 SHA256 核验；332 件复用相同缓存，350 件新下载。原作品不修改。
- 本地快照不是自动同步；更新前先通过公开 GET 刷新 `.local/object-stage-library/prompts.json` 和 `works.json`，再运行 `scripts/fetch-object-stage-library.py` 核验/读取资产，运行 `node scripts/prepare-object-stage.mjs --library` 并重启当前预览服务。不要用无参数 prepare 覆盖完整库，该模式仍输出原八件样本。

## 展台变化与就绪判断

可搜索的「全部题目」保留键盘/台灯快捷入口。一次最多两个隔离 iframe；同题继续从完整题内池轮换，并要求两件来自不同模型。盖箱、换面单、拆封和揭晓仍走原时间轴。慢加载 12 秒后可重新加载同组或直接换一组，选择继续锁定，实际就绪后恢复。

发现并修正了适配层把普通内部 `render()` 调用误判为 Three.js 场景，导致 WeakSet 报错的问题。排除离屏贴图和小图标的就绪信号，补上真实 WebGPU 提交、Canvas2D 像素绘制和大 SVG 场景的识别。仅本地响应移除原 WebGL-only 就绪探针，由本地桥接统一等待 DOM、实际绘制、加载遮层消失和连续两个稳定检查；无固定超时放行。相机控制能力与实际绘制分开，无已识别相机控制时复位禁用、不展示旋转手势引导。

本地内容服务沿用生产 CDN 白名单，移除仅本机批量预览的生产 IP 读取限额；主站/共享后端源码没有修改。

## 实载证据与边界

全 682 件首轮逐件浏览器加载：634 件在 16 秒内达到就绪，48 件超时，17 件产生运行错误。修正适配后，对首轮超时或有运行错误的 65 件串行复查：60 件就绪，剩 5 件超时；WeakSet 错误未再出现，仍有 2 件运行错误。两次证据合并为 677 件达到过真实就绪、5 件待调查，并非全部 682 件都在最终代码下重新跑过一次。两轮浏览器监听均没有非 GET/HEAD 写请求。

16 秒是这次检查的截止时间，超时不等于作品永远无法运行。真实绘制也不等于布局、相机、玩法交互或帧率全部合格；本轮没有逐件视觉审稿或真机 FPS 验收。

## 已告知的取库副作用

首次误用了远端 `createLibrary` 初始化入口：其过期草稿清理在数据库只读错误前删除了一个已过期上传临时目录。公开题目、作品与数据库行未写。当前取库脚本改为直接 SELECT 和静态 catalog，后续传输只读且校验原始哈希。这次操作不能描述为全程零远端文件写入；详情与读回证据见 HANDOFF 和 `.local/object-stage-library/inspect-draft-state.py`。

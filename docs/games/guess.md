# 模一把 · 玩法规则

Wordle 式每日猜 AI 模型的独立玩法（决策 057；难度分池 060；双模式拆分 064；079 四档；081 层叠）。本文是它的「玩法宪法」：规则口径、判定阈值、每日派生与数据集维护契约都在这里，代码注释与 `docs/DECISIONS.md` 不再重复展开。竞技场测评类玩法的规则仍在 `docs/PRODUCT.md`，本文只管模一把。

- 页面：`#guess`；入口：玩法菜单第四项。
- 实现：判定核心 `lib/guess-logic.ts`（纯函数，前后端同一份代码）、数据层 `lib/guess.ts`、页面 `app/guess.tsx` + `app/guess.css`、接口 `GET /api/guess/today`、`POST /api/guess/check` 与 `POST /api/guess/practice/start`（`server/index.js`）、校验 `npm run validate:guess`。

## 两种模式（决策 064/081）

进游戏先选模式：

- **每日一题**：全世界同一道题（东八区零点换题），答案从**普通池（简单+普通，difficulty ≤ 2）**种子派生——困难与地狱档不进每日（太冷门不利于分享传播）。战绩、连胜、分享只属于这个模式。结束后可「重玩今天」（重玩不再记战绩）。
- **练习模式**：选简单/普通/困难/地狱一档（079 起四档；081 起**层叠分池**：难度 k 的池 = `difficulty ≤ k` 的全部模型，档越高池越全，地狱=全库），**随机出题、不限次数**，答案由服务端开局时随机抽取并持有（`practice/start` 发 gameId，判定时带 gameId；服务器重启局失效，前端自动开新局；空池开局会被服务端明确拒绝）。练习**不计战绩、不上报统计**。结果横幅是「再来一把」——同难度立刻开新局。

## 一局怎么玩

1. 玩家在搜索框输入模型名（补全式：输入后才出匹配，在**全量模型库**里找、不按当前答案池过滤——猜池外模型也拿正常反馈，等于自愿加难度；已猜过的排除；匹配分隔符不敏感——"gpt 5"/"gpt5"/"sonnet4.5" 都能命中，多词乱序走逐词兜底；同档候选按发布时间倒序、最新模型排最前（输入全名时全等项永远第一），规则在 `searchGuessModels`），提交一次猜测。
2. 每次猜测对七个属性各给一格反馈（见下节），最多 8 次。
3. 猜中或 8 次用尽即结束，揭晓答案；每日题结束后可复制 emoji 格局分享。
4. 无需登录；每日对局按天存浏览器本地（`guess-session:<dayKey>`），练习局按难度存（`guess-practice:<难度>`），刷新接档。游戏中点左上角品牌、返回选择模式或模式标签均回选择屏，保留进度；选择屏再返回玩法菜单。

## 七属性与判定口径

| 属性 | 含义 | 反馈规则 |
| --- | --- | --- |
| 厂商 | 数据集 `org` 原文（如 "Zhipu AI (Z.ai)"，不做中文化） | 同厂商=绿；不同厂商但同国家/地区=黄（决策 062，如 xAI 与 OpenAI 同为美国）；跨国=灰。映射表 `VENDOR_REGION`，新增厂商必须登记 |
| 发布 | 正式发布年月（不算预告） | 同月=绿；差 ≤6 个月=黄+箭头；更远=灰+箭头 |
| 权重 | 是否开放权重可下载 | 同=绿，不同=灰；无黄色 |
| 上下文 | 上下文窗口（K token） | 相等=绿；比值 ≤2 倍=黄+箭头；更远=灰+箭头 |
| 模态 | **二元口径（2026-09-17）：只看「纯文本 / 多模态」**；数据集 `modality` 仍记细分输入集合（"text+image+video" 等），但判定不看细节 | 同纯文本=绿；同多模态=黄（**恒黄**，即使两边集合完全相同，也不细究图/音/视差别）；一纯文本一多模态=灰；无箭头 |
| 推理 | 是否思考链/深度思考型 | 同=绿，不同=灰；无黄色 |
| 价格 | 五档：0 近免费 / 1 便宜 / 2 中等 / 3 贵 / 4 旗舰。**取官方一手 API 输出单价（$/百万输出 token）划定**，边界 <$0.5 / <$2 / <$8 / <$25 / ≥$25（`PRICE_BAND_EDGES`，代码内可调） | 同档=绿；相邻档=黄+箭头；差 ≥2 档=灰+箭头 |

- **价格口径（2026-09-13 定稿）**：数据集 `priceOut` = 官方一手厂商的输出单价；**不用聚合商价格**（曾因「取各家最低价」被 OpenRouter 等的 `:free` 镜像污染，96/155 条标成免费，属性失去区分度，已废弃该口径）。没有一手价的（停产老模型、无一手 API 的开源模型）`priceOut=null`，格子显示「?」。揭晓条附具体价格（如 `$4.4/M`）。数据集中旧的字符串档 `priceTier` 字段已弃用，仅为 diff 校验保留；真正生效的档位由我们代码的 `PRICE_BAND_EDGES` 划定。

- **箭头**只出现在数值型属性（发布/上下文/价格）的非绿格上，指向答案相对该猜测的方向（↑=答案更大/更新/更贵）。
- **「?」（未公开）**：该属性数据集记为 null（当前 3 个老模型的 contextK 或 priceTier）。不计对错、无箭头——诚实呈现未知，不惩罚玩家。自己猜自己时，未公开属性也显示 ?。
- 黄色阈值（±6 个月 / 2 倍 / 相邻档）集中在 `lib/guess-logic.ts` 的 `GUESS_CONFIG` 与 `judge()` 内——**调手感只改那里**，不要散落复制。

## 每日答案怎么来

- epoch（第 0 天）= 2026-09-13（上线日）。`dayNumber` = 该日（UTC+8）距 epoch 的真实天数（`Date.UTC` 差，非月份近似）。
- 每日一题答案 = **每日池（`dailyPool` = 简单+普通，决策 064/081；困难与地狱档不进每日）** 内先按 `(dayNumber × 2654435761)` 散列取模选**答案槽**（数据集条目，合并组算一槽），组内再按「该槽历史上第几次被抽中」轮转实例化一个版本（决策 061）。练习模式不走路径派生——开局时服务端从所选难度池真随机抽取（组算一槽、组内随机版本），答案存服务端内存局表，只对该局有效。
- **槽分基础/追加两类（2026-09-14 修复）**：基础槽 = 主数据集条目（槽序按数据集顺序冻结）；追加槽 = 后台增量条目，带 `sinceDay`（生效日）。某日参与取模的槽数 = 基础槽数 + 当日已生效（`sinceDay ≤ dayNumber`）的追加槽数——后台追加模型从次日起才可能被抽为每日答案，当天与历史日期的答案一个不变。不能用「散列 % 全量槽数」：池子变长会让几乎所有日期取模移位（98→100 槽实测 60 天里 58 天换答案）。`validate:guess` 有「追加不改当天与历史答案」的回归断言。
- 每日题无随机源：同一天任何时刻、任何实例算出的答案一致（含组内版本）；十年周期内全槽位覆盖、组内每个版本都会被实例化。
- epoch 与散列常数冻结，**改任何一个=重排全部历史答案**，上线后勿动。同理，**调整某模型的 `difficulty` 会重排它涉及的池的历史答案**（简单/普通档的调动影响每日题；层叠下波及 ≥该档的所有池）——分池冻结已由机器把关（`validate:guess` 的槽位指纹断言，见下节「难度分池的冻结与定稿」），只能用户显式拍板后走定稿流程。
- 答案只在服务端派生/持有；`/api/guess/check` 只有猜中或第 8 次（`final:true`）才随响应附带答案，防「查看源码」与试探。

## 数据集维护契约（重要）

`lib/guess-models.json`，168 个答案槽（含 21 个合并组）、204 个可猜模型名（081 第一版映射后），主体大致按 `popularity` 降序、081 追加的 66 条在数组末尾（来源：models.dev 快照 + 人工整理，外部 AI 协作产出，updatedAt 见文件头）。全量明细清单见同目录 `_dataset-review.md`（生成物，可随时重出）。

- **追加新模型只能放 `models` 数组末尾**。主数据集的槽序按首次出现顺序冻结，插入或重排会改变历史日期的答案——昨天晒出的分享图不能变卦。组内追加版本同理：只加在 `variants` 末尾（轮转次序按下标）。
- **后台追加通道（决策 063）**：后台「模一把」页可手动追加新模型——写入 `data/guess-models-extra.json`（服务器本地数据，不入库，格式 `{ vendorRegions, models }`；写入先落 `.tmp` 再改名，原子替换），服务端启动时经 `registerExtraModels` 合并到数据集末尾并即时生效（不重启）。**追加条目必须带 `sinceDay`（= 追加次日；2026-09-15 起强制校验，缺失整批拒绝）**：立即进候选与练习池，从次日起才参与每日题派生（见上文「基础槽/追加槽」）——当天与历史答案不受追加影响。只能追加、不能改已有条目（改难度/重排=重排历史答案，仍走改主数据集流程）；增量文件不支持合并组；新厂商须在 `vendorRegions` 里登记地区（后台表单强制）。`registerExtraModels` 两阶段提交：批次里有 id 冲突（含批次内重复）或坏条目时整体拒绝，不会部分注册，`vendorRegions` 一并回滚。`validate:guess` 对存在的增量文件做结构校验（含 sinceDay 必填）。
- **合并组（决策 061）**：同线小版本（只差月份与零星座位的兄弟模型，如 Qwen3.5/3.6/3.8 27B）合并为一个组条目，`name` 用占位写法（"Qwen3.x 27B"），具体版本放 `variants` 数组（每条是字段完整的普通条目，但不带 `difficulty`——分池以组为单位，组内版本继承组难度）。组条目只占一个答案槽、本身不可猜；抽中该组时按命中次序轮转实例化一个版本作为当日答案。玩家猜组内邻近版本会得到「全绿只差月份」——版本号就是这类题的最后一层推理。收录原则：越古老的代际合并越多，参数后缀名（"480B A35B" 这类规格表条目）不成组就删，新模型分开。
- 字段口径：`id`（稳定 kebab）、`name`（唯一显示名）、`org`（厂商显示名原文）、`year`/`month`、`openWeights`、`contextK`（K token，null=未公开）、`modality`（`+` 拼接，如 "text+image"）、`reasoning`、`priceOut`（官方一手输出单价 $/M，null=无一手价；价格档由我方代码划定，数据集不负责分档）、`popularity`、`difficulty`（1 简单 / 2 普通 / 3 困难 / 4 地狱——**层叠语义（081）：值 =「最低从哪一档开始出现」，难度 k 的池 = `difficulty ≤ k`**；081 第一版映射（2026-09-16，用户拍板，后续会改）：29 个困难档条目退役入地狱、追加 66 条新模型，当前分布（专属档，槽口径）简单 40 / 普通 33 / 困难 66 / 地狱 29，层叠池大小 40 / 73 / 139 / 168 槽）；`priceTier`（旧字符串档，已弃用，仅 diff 校验保留）。
- 上游换字段结构时只改 `lib/guess-logic.ts` 顶部的适配层（`normalizeModel` 与 `PRICE_TIER_MAP`），判定逻辑永远吃内部模型。
- 改完跑 `npm run validate:guess`：id/name 唯一、日期合法、值域检查都在里面。
- 属性语义的口径疑问（如「发布日算不算预告期」「某模型价格归哪档」）以数据集维护方为准，本仓库只做结构校验。

## 难度分池的冻结与定稿（决策 079/081）

四档难度：1 简单 / 2 普通 / 3 困难 / 4 地狱（079 扩档；**081 起为层叠语义**：`difficulty` 字段值 = 该模型最低从哪一档开始出现，难度 k 的池 = `difficulty ≤ k` 的全部模型——简单 ⊂ 普通 ⊂ 困难 ⊂ 地狱=全库）。每日池 = 普通池（≤ 2），困难与地狱只进练习模式。`guess_results.difficulty` 流水口径不变：0=每日题、1-3=旧三档时期历史；练习不上报，流水里永远不会出现 4。

**为什么冻结由机器把关**：`difficulty` 决定答案池成员，池成员一变，该池（层叠下为 ≥该档的所有池）全部历史日期的派生答案就重排（每日题尤甚）。过去这条红线靠口头约定，2026-09-16 起由 `scripts/validate-guess.mjs` 的「分池冻结」断言钉住：主数据集每档的**专属**槽位构成（`difficulty === k`；组算一槽，槽 id 排序 sha256 前 16 位）写在 `POOL_FINGERPRINTS` 常量里，任何人不经意改了分池，`validate:guess` 直接失败。

**为什么 081 这轮允许大规模重排**：用户明确「项目还没上线，历史答案不管」——这是预期内的一次性豁免，不成为先例；每日题历史越长，重排代价越大。

**定稿流程（唯一合法的调档路径）**：
1. 用户给出明确映射：哪些模型（含合并组，分池以组为单位）从哪档移到哪档，并说明理由。
2. 改 `lib/guess-models.json` 的 `difficulty` 字段（组改组条目，变体继承），不动 id/name/数组顺序。
3. 跑 `npm run validate:guess`，冻结断言必然失败——这是预期的。
4. 重算各档专属槽位指纹（槽 id 排序后 sha256 前 16 位），更新 `POOL_FINGERPRINTS`，再跑确认全绿。
5. 在 `docs/DECISIONS.md` 记一条决策：谁、何时、哪些模型、从哪档到哪档、为什么现在做。
6. 重新生成 `_dataset-review.md` 明细清单。

**定稿之后仍被禁止的**：主数据集的任何增删（包括末尾追加——新模型只能走后台增量通道带 `sinceDay`）、改 epoch、改散列常数、以及绕过上述流程的任何 `difficulty` 调整。后台增量模型的难度选择在追加时指定、不受指纹约束（追加本就不影响历史），但**已有条目永远不可改档**。

## 本地存储与战绩

**对局不落盘（2026-09-14 用户拍板）**：两种模式的对局都只在页面内存里——退出、返回选择屏或刷新即清盘重开。每日一题重新进入仍是同一道（当日种子派生）；练习模式每次进入都向服务端开新局（随机抽题）。旧 `guess-session:` / `guess-practice:` 键不再写入（`resetGuessData` 会顺带清掉历史遗留）。

- 结算标记：`localStorage['guess-settled:<dayKey>']`（一天一条 `'1'`）——每日一题战绩已结算过。这是「今天玩没玩完」的唯一持久记录：刷新后选择屏角标显示「今日战绩已记录」，再进再赢不重复结算、不重复上报。
- 战绩：`localStorage['guess-stats']`（场次/胜场/连胜/最少步数）+ `guess-last-day`（连胜判定锚点），**只记每日一题**，练习不进战绩。口径：只有「玩了且输了」才断连胜，隔天没玩不断（Wordle 同款宽松口径）。
- 旧档迁移：三档难度时期（060）的 `guess-stats:1` 读取时并入 `guess-stats`（一次性）；对局落盘时期的 `guess-session:`/`guess-practice:` 记录不迁移，自然作废。
- 清理：`lib/guess.ts` 的 `resetGuessData()`（调试用，正常用户路径不暴露）。
- 游玩数据上报（决策 063/064）：每日对局首次结算（与 `guess-settled` 同一时机，一局一条）时前端匿名 `POST /api/guess/result`（dayKey/胜负/步数，不再带难度——每日题记 difficulty=0）；answer_id 由服务端按 dayKey 从每日池重新派生、客户端无从伪造归属（2026-09-15 起日期往返核对，`2026-11-31` 这类不存在的日子拒收）；落 `guess_results` 表供后台「模一把」页统计。练习模式不上报；手动「看答案」按负场结算并上报，中途关页的局不报；失败静默不影响游玩。
- **「直接看答案」按钮（2026-09-15 修复）**：对局进行中、且已猜过至少一次时显示在搜索框下方（拿已猜过的模型再发一次 final 请求取答案）。原先按钮放在结果面板里，而 `finished` 与 `revealed` 恒同时翻转，显示条件永远不成立——按钮从未出现过。
- **跨零点守护（2026-09-15）**：每日题提交/看答案前比对当前 UTC+8 dayKey 与开局 dayKey，不一致（页面跨过东八区零点还开着）就拉新题、换到新一天的棋盘并提示——旧棋盘继续猜会把两个答案混进一局、战绩记错日子。练习模式答案在服务端局内存里，不受影响。
- **限流（2026-09-15 分组）**：`/api/guess/*` 三个写接口共用独立的「guess」桶（默认 30 次/分钟/IP），不再与评论/投票共抢全站 10 次额度；429 时前端提示「请求太频繁，稍等几秒再试」。
- 无账号绑定；将来联机/账号并入时按记录全量重算即可。

## 已知边界与小瑕疵

- 多人对战/好友对决：用户已列为后续意向，未授权开工。
- 价格五档边界在代码 `PRICE_BAND_EDGES` 里（见属性表），调手感不用找数据集；`priceOut` 是原始事实，会随官方调价过期，靠数据集更新。
- 战绩条在结算当次不实时刷新（刷新页面后正确）——已知瑕疵；2026-09-14 用户要求视觉轮暂不处理。
- 搜索无别名表（"chatgpt" 这类俗称搜不到），靠子串匹配兜底；别名表是数据集后续增强项。

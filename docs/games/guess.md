# 模一把 · 玩法规则

Wordle 式每日猜 AI 模型的独立玩法（决策 057；难度分池 060；双模式拆分 064；079 四档；081 层叠）。本文是它的「玩法宪法」：规则口径、判定阈值、每日派生与数据集维护契约都在这里，代码注释与 `docs/DECISIONS.md` 不再重复展开。竞技场测评类玩法的规则仍在 `docs/PRODUCT.md`，本文只管模一把。

- 页面：`#guess`；入口：玩法菜单第四项。
- 实现：[判定核心](../../lib/guess-logic.ts)、[客户端数据层](../../lib/guess.ts)、[页面](../../app/guess.tsx) + `app/guess.css`。动态接口由共享后端 arenaofbias-server 的 `server/show1/guess.mjs` 提供：`GET /api/guess/today`、`POST /api/guess/check`、`POST /api/guess/practice/start` 与 `POST /api/guess/result`；本仓 `server/index.js` 是迁移前实现。规则校验 `npm run validate:guess`，本机存档校验 `npm run validate:guess-session`。

## 两种模式（决策 064/081）

进游戏先选模式：

- **每日一题**：全世界同一道题（东八区零点换题），答案从**简单、普通中的精选池（difficulty ≤ 2 且 dailyEligible=true）**种子派生——困难与地狱档不进每日（太冷门不利于分享传播）。战绩、连胜、分享只属于这个模式。进度保存在当前浏览器，退出或刷新后可以续局；猜中、8 次用尽或直接看答案后，当天棋盘锁定，只能查看结果或转去练习，不能「重玩今天」。
- **练习模式**：选简单/普通/困难/地狱一档（079 起四档；081 起**层叠分池**：难度 k 的池 = `difficulty ≤ k` 且有出题资格的模型，档越高池越全，地狱包含全部可出题模型），**随机出题、不限次数**，答案由服务端开局时随机抽取并持有（`practice/start` 发 gameId，判定时带 gameId；服务器重启局失效，前端自动开新局；空池开局会被服务端明确拒绝）。练习**不计战绩、不上报统计**。结果横幅是「再来一把」——同难度立刻开新局。

## 一局怎么玩

1. 玩家在搜索框输入模型名（补全式：输入后才出匹配，在**全量模型库**里找、不按当前答案池过滤——猜池外模型也拿正常反馈，等于自愿加难度；已猜过的排除；匹配分隔符不敏感——"gpt 5"/"gpt5"/"sonnet4.5" 都能命中，多词乱序走逐词兜底；同档候选按发布时间倒序、最新模型排最前（输入全名时全等项永远第一），规则在 `searchGuessModels`），提交一次猜测。
2. 每次猜测对七个属性各给一格反馈（见下节），最多 8 次。
3. 同一模型或七条实际线索完全一致均算猜中；未知值只与未知值相等，不是通配符。猜中或 8 次用尽即结束，揭晓答案；每日题结束后可分享（服务端生成图片卡，见「分享」节）。
4. 无需登录。每日题在成功猜测或揭晓后立即保存到本机，返回选择屏、退出或刷新不清进度；选择屏分别显示「今天还没玩」「继续今日挑战」「查看今日结果」。练习只保留当前页面的对局内存，返回选择屏后再次进入或刷新都重新开局。游戏中点左上角品牌、返回选择模式或模式标签均回选择屏；选择屏再返回玩法菜单。

## 七属性与判定口径

| 属性 | 含义 | 反馈规则 |
| --- | --- | --- |
| 厂商 | 数据集 `org` 原文（如 "Zhipu AI (Z.ai)"，不做中文化） | 同厂商=绿；不同厂商但同国家/地区=黄（决策 062，如 xAI 与 OpenAI 同为美国）；跨国=灰。映射表 `VENDOR_REGION`，新增厂商必须登记 |
| 发布 | 正式发布年月（不算预告） | 同月=绿；差 ≤6 个月=黄+箭头；更远=灰+箭头 |
| 权重 | 是否开放权重可下载 | 同=绿，不同=灰；无黄色 |
| 上下文 | 上下文窗口（K token） | 相等=绿；比值 ≤2 倍=黄+箭头；更远=灰+箭头 |
| 模态 | 数据集 `modality` 的完整输入集合（如 "text+image+video"），比较时不计排列顺序与重复项 | 完整集合相同=绿，与模型身份无关；集合不同但都为多模态=黄；一纯文本一多模态=灰；无箭头（2026-09-29 用户确认） |
| 推理 | 是否思考链/深度思考型 | 同=绿，不同=灰；无黄色 |
| 价格 | 六档：0 近免费 / 1 便宜 / 2 中等 / 3 贵 / 4 旗舰 / 5 顶档。**取题库采用的 API 输出单价（$/百万输出 token）划定**，边界 <$0.5 / <$2 / <$8 / <$25 / <$50 / ≥$50（`PRICE_BAND_EDGES`，代码内可调） | 同档=绿；相邻档=黄+箭头；差 ≥2 档=灰+箭头 |

- **价格口径（2026-10-16 用户更新）**：`priceOut` 优先取官方标准短上下文文本输出价；缺少一手价时，允许采用有来源的历史官方价或指定托管商的标准价格。每条固定型号、服务商与地区，来源、日期、单位和取舍保存在核验清单的 `priceReview`，界面不增加“参考”标记。**不取全网最低价，不用免费额度、`:free` 镜像、包月费或按小时的部署成本**，避免再次把大量模型错误归为免费。完全没有可靠依据的仍为 null；揭晓条沿用具体价格（如 `$4.4/M`），格子仅显示代码统一派生的档位。
- 本次补齐 19 条价格，缺价从 35 降至 16；补价阶段未改出题资格；随后用户指定 dots3 note Preview 固定为“近免费”。本轮重新分池将仍缺少价格或上下文线索的 18 个型号改为仅供搜索，四档自动答案均无线索问号。dots3 的实际 API 单价仍未核实，游戏档位遵照用户决定。保留价未在本轮全部重新核验。

- **固定游戏档位**：仅经用户明确决定的主数据集条目可带 `priceTierOverride`，优先于报价派生且不对后台追加开放。目前仅 dots3 note Preview 固定为 0（近免费），即使以后报价变化也不自动改档；`priceOut` 仍独立保存有依据的真实报价，不因固定档位而虚填。

- **箭头**只出现在数值型属性（发布/上下文/价格）的非绿格上，指向答案相对该猜测的方向（↑=答案更大/更新/更贵）。
- **「?」（未知）**：该属性数据集记为 null（contextK 或 priceTier）。不计对错、无箭头——诚实呈现未知，不惩罚玩家。自己猜自己时，未知属性也显示 ?。
- 黄色阈值（±6 个月 / 2 倍 / 相邻档）集中在 `lib/guess-logic.ts` 的 `GUESS_CONFIG` 与 `judge()` 内——**调手感只改那里**，不要散落复制。

## 每日答案怎么来（2026-10-16 修复）

- epoch 仍为 2026-09-13，日期按 UTC+8。答案池为 `dailyPool`：难度 ≤2、`answerEligible !== false` 且 `dailyEligible === true`。
- 使用按稳定 ID 确定性排列的周期题单，一个周期内每个答案槽出现一次，合并组算一槽；组内版本按周期轮转。消除旧乘法取模和池长共振导致的少数槽位反复出现。相同题库、相同日期始终得到同一答案，数组重排不改变结果。
- 周期开始时冻结已经生效的槽和变体；后来加入的模型及组内新变体都带 `sinceDay`，进入生效日之后的下一周期，因此不插队重排正在进行的周期或历史答案。后台追加立即可搜索/用于练习，每日出题可能要等当前周期结束。
- 本轮用户明确允许重排历史答案；旧分享链接按日期重新派生时可能显示新答案，但不删除历史统计。后续更换规则或修改已有条目仍须明确授权。
- 答案只在服务端派生；猜中或 `final:true` 时揭晓。单人玩法的公开分享卡仍按日期展示答案，不作为防作弊成绩凭证。

## 数据集维护契约（重要）

`lib/guess-models.json` 当前 217 个可搜索模型（新增 13 个），其中 181 个可自动出题、36 个仅供搜索（原有 3 个特殊条目、18 个线索不完整条目、15 个同线索非代表型号）。四档层叠答案模型数为 24/106/166/181，对应 24/80/136/149 个槽；每日精选 54 个模型、53 个槽。修正明细与来源见 [2026-10-16 核验清单](guess-catalog-review-20261016.json)。这份清单记录已确认的字段修正，不代表所有旧资料已逐字段重新核实；后续补价记录在 `priceReview`，保留前一轮修正的历史记录。

- 新模型追加在数组末尾，便于审计；新条目及组内新变体都需 `sinceDay`。稳定 ID 不改、不复用。别名可用 `aliases`，不得混淆不同版本。
- **后台追加通道**：共享后端 `server/show1/guess-admin.mjs` 实现 GET 统计、GET 模型、POST 追加，要求现有高级管理员身份；写请求校验来源、限流、大小和字段。文件在 `config.dataDir/guess-models-extra.json`，默认 `.data/`，原子替换，重启重载，不入 Git。后台只追加、不修改已有模型，新条目默认不进每日池；后台明确勾选 `dailyEligible` 且难度≤2、线索完整才有每日资格，从追加次日之后首个完整周期纳入。资料不全或已有同线索代表时，仅供搜索。
- 增量注册先完整验证再应用：重复 ID/规范化名称、非法年月/难度/价格/上下文、缺 `sinceDay`、坏模态、缺厂商地区等整批拒绝，避免文件写坏或半批生效。展示、检索包含 lookup-only 条目；每日/练习/好友房抽题统一排除它们。
- **合并组（决策 061）**：同线小版本（只差月份与零星座位的兄弟模型，如 Qwen3.5/3.6/3.8 27B）合并为一个组条目，`name` 用占位写法（"Qwen3.x 27B"），具体版本放 `variants` 数组（每条字段完整，默认继承组难度；2026-10-16 用户批准代表型号单独降档，允许变体用 `difficulty` 覆盖）。组条目只占一个答案槽、本身不可猜；抽中该组时按命中次序轮转实例化一个版本作为当日答案。玩家猜组内邻近版本会得到「全绿只差月份」——版本号就是这类题的最后一层推理。收录原则：越古老的代际合并越多，参数后缀型号保留搜索，细分规格提高难度；七条线索完全相同只留一个自动答案代表，猜等价型号仍算赢。未确认的泛称或线索不全条目不自动出题。
- 字段口径：`id/name/org/year/month/openWeights/contextK/modality/reasoning/priceOut/popularity/difficulty`；`contextK` 用 1000 token 为 1K、四舍五入，取官方支持窗口而非输入与输出相加；权重必须实际可下载；价格按上面的来源优先级，统一为美元/百万文本输出 token，无可靠价格填 null，不把其他版本的价格移植过来；权重等必填事实未确认的条目暂缓录入。
- `verification` 记录本轮已核验字段、来源和日期。更新事实会改变线索，需同步题库版本与会话恢复。
- 判定唯一源为 `lib/guess-logic.ts`；`node scripts/sync-guess-core.mjs --backend=<共享后端绝对目录> --write` 生成后端核心及模型表。不带 `--write` 做一致性检查，不能在两边手工维护不同规则。
- 验证：`npm run validate:guess`、`node scripts/validate-guess-catalog.mjs`、`npm run validate:guess-session`，以及后端 guess/好友房回归。

## 难度分池的冻结与定稿（决策 079/081）

四档难度：1 简单 / 2 普通 / 3 困难 / 4 地狱（079 扩档；**081 起为层叠语义**：`difficulty` 字段值 = 该模型最低从哪一档开始出现，难度 k 的池 = `difficulty ≤ k` 且有出题资格的模型——简单 ⊂ 普通 ⊂ 困难 ⊂ 地狱包含全部可出题模型）。每日池是≤2的单独精选子集，困难与地狱不进每日。`guess_results.difficulty` 流水口径不变：0=每日题、1-3=旧三档时期历史；练习不上报，流水里永远不会出现 4。

**为什么冻结由机器把关**：`difficulty` 决定答案池成员，池成员一变，该池（层叠下为 ≥该档的所有池）全部历史日期的派生答案就重排（每日题尤甚）。过去这条红线靠口头约定，2026-09-16 起由 `scripts/validate-guess.mjs` 的「分池冻结」断言钉住：主数据集每个模型的 `[id,difficulty,answerEligible,dailyEligible,groupId或id]` 按 id 排序，JSON 的 SHA-256 写在 `POOL_FINGERPRINT` 常量里，任何人不经意改了分池，`validate:guess` 直接失败。

**历史规则豁免**：081 用户曾明确允许历史重排；2026-10-16 用户再次明确“改历史其实无所谓”，授权本轮修复每日派生及事实，后续不得把本次授权当无限期许可。

**定稿流程（唯一合法的调档路径）**：
1. 提出具体分池原则与代表型号，取得用户确认；在核验清单保存逐型号的前后映射和理由。本轮用户授权整体执行，完整映射见 `guess-catalog-review-20261016.json` 的 `difficultyReview`。
2. 改 `lib/guess-models.json` 的 `difficulty` 字段（组提供默认值，变体可覆盖），不动 id/name/数组顺序。
3. 跑 `npm run validate:guess`，冻结断言必然失败——这是预期的。
4. 重算模型级资格与分池指纹（含每日精选），更新 `POOL_FINGERPRINT`，再跑确认全绿。
5. 在 `docs/DECISIONS.md` 记一条决策：谁、何时、哪些模型、从哪档到哪档、为什么现在做。
6. 重新生成 `_dataset-review.md` 明细清单。

**定稿之后仍被禁止的**：未经授权更换规则/epoch、无 `sinceDay` 增加模型或变体，以及绕过上述流程的任何 `difficulty` 调整。后台增量模型的难度选择在追加时指定、不受指纹约束（追加本就不影响历史），但**已有条目永远不可改档**。

## 本地存储与战绩

**每日按浏览器存档，练习只在内存（2026-09-26 修复，本轮合入）**：每日题在当前浏览器保存轨迹和完成状态，重新进入时恢复；练习每次进入都向服务端开新局（随机抽题），不恢复旧局。存档不绑定账号，也不同步其他设备或浏览器。旧 `guess-session:` / `guess-practice:` 键不再写入（`resetGuessData` 会顺带清掉历史遗留）。

- 每日轨迹：`localStorage['guess-daily:<dayKey>']` 存版本号、猜测模型 ID 与七属性反馈、胜负、完成/揭晓状态及已揭晓答案 ID；恢复时以今日接口返回的模型列表重建展示。每次成功猜测和主动揭晓都保存；猜中、8 次用尽、直接看答案均完成并锁定当日棋盘。
- 结算标记：`localStorage['guess-settled:<dayKey>']`（一天一条 `'1'`）表示每日战绩已结算，避免重入后重复结算和上报。旧版本只有结算标记而没有轨迹时，仍显示已完成状态，不允许重开；没有轨迹可分享时不显示分享按钮。
- 跨标签：支持 Web Locks 时，按 `aob-guess:<dayKey>` 串行执行每日提交、揭晓和结算；其他标签通过 storage 事件同步轨迹与战绩，提交前还会读取较新的持久状态。浏览器不支持 Web Locks 时仍做状态核对，但不保证并发提交原子执行。
- 存储不可用：当前页面以内存保留每日进度与结算标记；刷新后的恢复、跨标签同步和持久锁定不保证。清除浏览器存储也会清除本机记录，不能把它视为服务端防重复游玩的凭证。
- 战绩：`localStorage['guess-stats']`（场次/胜场/连胜/最少步数）+ `guess-last-day`（连胜判定锚点），**只记每日一题**，练习不进战绩。口径：只有「玩了且输了」才断连胜，隔天没玩不断（Wordle 同款宽松口径）。
- 旧档迁移：三档难度时期（060）的 `guess-stats:1` 读取时并入 `guess-stats`（一次性）；对局落盘时期的 `guess-session:`/`guess-practice:` 记录不迁移，自然作废。
- 清理：`lib/guess.ts` 的 `resetGuessData()`（调试用，正常用户路径不暴露）。
- 游玩数据上报（决策 063/064）：每日对局首次结算（与 `guess-settled` 同一时机，一局一条）时前端匿名 `POST /api/guess/result`（dayKey/胜负/步数，不再带难度——每日题记 difficulty=0）；answer_id 由服务端按 dayKey 从每日池重新派生、客户端无从伪造归属（2026-09-15 起日期往返核对，`2026-11-31` 这类不存在的日子拒收）；落 `guess_results` 表供后台「模一把」页统计。练习模式不上报；手动「看答案」按负场结算并上报，中途关页的局不报；失败静默不影响游玩。
- **「直接看答案」按钮（2026-09-15 修复）**：对局进行中、且已猜过至少一次时显示在搜索框下方（拿已猜过的模型再发一次 final 请求取答案）。原先按钮放在结果面板里，而 `finished` 与 `revealed` 恒同时翻转，显示条件永远不成立——按钮从未出现过。
- **跨日与资料更新**：today 返回 `catalogVersion`；check 校验客户端 dayKey 和版本，分别返回 409 `daily-changed` / `catalog-changed`，客户端重新取题库并恢复或重建棋盘。未完成旧版本每日存档重置并提示，已完成仍锁定，不重复结算、不清累计战绩。旧接口调用者不带版本时兼容接受；上线需同步前后端并刷新旧页面，旧 JS 不认识第六价格档。

- **限流（2026-09-15 分组）**：`/api/guess/*` 三个写接口共用独立的「guess」桶（默认 30 次/分钟/IP），不再与评论/投票共抢全站 10 次额度；429 时前端提示「请求太频繁，稍等几秒再试」。
- 无账号绑定；将来联机/账号并入时按记录全量重算即可。

## 已知边界与小瑕疵

- 双人好友房已作为独立 `#guess-friends` 实现，规则见下节；多人、公开匹配与聊天未实现。
- 价格六档边界在代码 `PRICE_BAND_EDGES` 里（见属性表），调手感不用找数据集；`priceOut` 是题库采用的有来源价格，可能随厂商或托管商调价过期，靠带核验记录的数据集更新。
- 每日结算后刷新当前页面战绩；其他标签通过 storage 事件同步。记录仍由本机浏览器维护，无法作为服务端认证成绩。
- 搜索支持显式别名、中文厂商/系列名及全半角规范化。歧义名称不能自动映射为某个具体模型。
- 视觉维护入口为 `app/guess.tsx` 与 `app/guess.css`：反馈状态保留 hit/near/miss/unknown 四个语义 class，颜色集中在 `--guess-*` 变量。

## 双人好友房（2026-10-14，本地实现）

- 入口：模一把模式选择页「双人好友房」，hash `#guess-friends`。两人都需要现有平台账号登录；创建者选难度，把 8 位房间码发给另一人。一个账号同时只参加一间进行中的房间。
- 双方准备后倒数 3 秒开始。同一轮答案相同且由服务器随机抽取；每人 8 次、每轮 120 秒，先猜中得 1 分，先得 2 分获胜。双方用尽次数或到时仍未猜中为平局，不加分，6 秒间隔后自动换题。复用既有七属性判定与难度池，不改每日派生器。
- 对局中只看自己的模型与完整线索，对方只收到七格颜色（响应里也不含模型名/ID和方向）；本轮结束后才公开答案与双方猜测。
- 房间、答案、次数、比分、截止时间和请求去重由共享后端持有，SQLite 持久化。首轮开始冻结整场题库和规则版本，后续轮次与重连继续使用该快照；更新题库不会改变进行中对局的线索。升级前缺少快照的旧房间中性结束，不记双方输赢。刷新/短时重连恢复原座位与进度，不重新计时。对局中主动离开判本场负，断线 30 秒判负；两人都超时则结束且无胜者。等待房的房主离线 30 秒关闭房间，客人离线释放空位；等待最长 15 分钟，对局最长 1 小时，结果保留 1 小时。
- 使用现有 HttpOnly 会话；房间码是加入邀请，不是读取/操作身份。所有请求校验登录、来源和座位；限频、2 人上限、单账号最多 2 条推送、活动房间容量和过期清理均在服务端执行。判定请求带轮次及唯一请求 ID，网络重试不会多扣次数或重复计分。旧单人揭晓接口不能揭晓好友房答案。
- 联机使用 HTTP 提交 + SSE 推送；推送不可用时每 3 秒最多一次状态同步，单请求 12 秒截止。没有公开房间列表、聊天、随机匹配或观战入口；不写每日挑战本地存档、`guess_results` 或个人每日战绩。
- 部署依赖共享后端追加迁移（当前本地 v43）及 `server/show1/guess-rooms.mjs`、`guess-room-http.mjs`。本仓旧 Express 服务不提供好友房。先部署兼容的后端再上线前端；本轮未提交或部署。
